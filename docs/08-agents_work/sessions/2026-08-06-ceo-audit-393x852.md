# Audit — 393×852, the only viewport that matters

page (`__reactFiber$` present on `nav[aria-label="Main"]`), not read from source and

## P1 — Founder-named, and they break the object

**1. The Book has no left edge.** `/book`, closed cover
(`under-lamp relative bg-cover bg-center z-10 -ml-9 …`) measures **392×505, ratio
0.776**, box **x = −42.8 → 348.8**. The `-ml-9` (−36px) puts the spine off-screen. You
never see the object's left edge, so it reads as olive cloth filling the screen rather
than a book resting on a table. 8 elements overflow the viewport on this route. This is
the founder's *"the book is not in the correct sizes."*

**2. Dates is a different product.** 0 law-era markers, 15 SaaS-era. White rounded cards
with borders and shadows, Lucide icons in grey `.well` circles, pill badges
("Eva writes next"), a black pill rail. **A single frame contains both worlds** — the
law-era paper tray sits at the bottom of a screen that is pure 2019 SaaS. This is the
founder's *"looks like a three years old website design,"* and it is still shipping.
Echo and Send are the same build.

   - **The bleed is correct and stays.** It is LAW §4 move #1 as written: one element,
     one edge, three edges visible, tear kept on the non-bleeding side. Defended as

     `washi-terracotta.webp` on the sealed note at x = −5.3 → 73.2, sliced by the
     **left** edge. That one is a genuine defect (a fastener with no visible end is
     not holding anything) and is fixed separately via `ml-3` → `ml-8`.

9. **The Book's proportion is not a margin problem — it is a coupling bug.**
   Found by Design-Lead, missed by this audit. The board's height is fixed

   fore-edge's growth is subtracted from the cover: board = 406 − foreEdge. Today

   changes shape as the archive thickens.** My finding (the −42.8 left edge) is a real

## Two false alarms I caught on myself

Recorded because this project's most expensive failures are all of this shape.

1. **The dark vertical strip on `/today`'s right edge is the scrollbar thumb**, not a
   layout defect. Thumb length = 852 × (852/1553) = 467px sitting at track bottom, which
   matches the observed y≈385→852 exactly. I was one step from filing it.
2. **"Day and night look identical" was wrong.** I compared two image reads by eye and
   concluded dark mode was unwired. Decoding the actual pixels showed a 23.5% dim. The
   host Chrome follows the OS scheme, so my first "day" capture was already dark —
   `emulateMedia` is mandatory, and eyes are not an instrument.

3. **I named the wrong element and the wrong material** on Today's top-right, and
   called a correct composition a defect. Caught by Design-Lead, not by me. A slice
   *was* there — on the sealed note's tape, at the opposite edge. Seeing a real
   symptom and attributing it to the nearest plausible cause is the same failure as
   the two above, one step later in the reasoning.

**A measurement can be as unexamined as a report.** The first two were caught by
measuring instead of looking. The third needed a second pair of eyes with more
domain knowledge than mine — which is the argument for the review gate existing at
all, and for briefing agents to argue back.

## Method notes for whoever runs this next

- `localhost`, never `127.0.0.1` — different origin, hydration silently never commits.
- Prove hydration before trusting any interaction (`__reactFiber$` on a real node).
- Viewport captures only. Full-page captures paint `position: fixed` at its document
  offset and lie.
- `emulateMedia({colorScheme})` explicitly in both directions; do not trust the default.
- Decode pixels for anything tonal. PIL is available.
